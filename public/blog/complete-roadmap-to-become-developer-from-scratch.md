## Can You Really Become a Developer Without a Degree?

**Yes.** The tech industry is one of the few where skills matter more than credentials. Companies like Google, Apple, and IBM have dropped degree requirements. What matters is: **Can you build things?**

This roadmap takes you from absolute zero to job-ready in 6-12 months.

## Phase 1: Foundations (Month 1-2)

### Week 1-2: How the Internet Works
Before writing code, understand the basics:
- How websites work (client-server model)
- What are domains, hosting, DNS
- HTTP/HTTPS basics
- How browsers render pages

**Free resources:** CS50 (Harvard), freeCodeCamp

### Week 3-6: HTML & CSS
Your first real skills:
- HTML structure and semantic tags
- CSS styling, flexbox, grid
- Responsive design (mobile-first)
- Build 3-5 simple static websites

### Week 7-8: JavaScript Basics
The language of the web:
- Variables, functions, loops, conditionals
- DOM manipulation
- Events and interactivity
- Build a calculator, to-do list, quiz app

## Phase 2: Intermediate (Month 3-5)

### Choose Your Path
At this point, decide your direction:

- **Frontend:** React/Vue/Angular → UI development
- **Backend:** Node.js/Python/Java → server-side logic
- **Full Stack:** Both (harder, takes longer)

Not sure? [Take our career quiz](https://www.skillta.tech/quiz) to find your best fit.

### Frontend Path (React)
- React fundamentals (components, props, state)
- Hooks and state management
- API integration (fetch, axios)
- Routing and navigation
- Build 3 projects: portfolio, weather app, e-commerce site

### Backend Path (Node.js)
- Node.js and Express basics
- REST API design
- Database fundamentals (SQL + MongoDB)
- Authentication and authorization
- Build 3 projects: REST API, blog backend, chat server

## Phase 3: Professional Skills (Month 6-8)

### Git & GitHub
- Version control basics
- Branching, merging, pull requests
- Contributing to open source
- Building a GitHub profile

### Tools & Practices
- VS Code mastery
- Chrome DevTools
- Testing basics
- CI/CD concepts

### Soft Skills
- Technical writing (README, documentation)
- Communication (standups, code reviews)
- Problem-solving approach (break down, research, implement)

## Phase 4: Job Preparation (Month 9-12)

### Build a Portfolio
You need 4-5 **quality** projects:
1. A personal portfolio website
2. A CRUD application with auth
3. An API integration project
4. A collaborative/real-time app
5. An open-source contribution

### Resume & LinkedIn
- ATS-optimized resume
- Strong LinkedIn profile
- GitHub with green squares
- Technical blog (optional but helpful)

### Interview Prep
- Data structures & algorithms (LeetCode easy/medium)
- System design basics
- Behavioral questions (STAR method)
- Mock interviews

## Common Mistakes to Avoid

1. **Tutorial hell** — Watch one tutorial, then build without following along
2. **Learning too many technologies** — Master one stack before exploring others
3. **Ignoring fundamentals** — JavaScript basics matter more than React tricks
4. **Not building projects** — Reading docs ≠ knowing how to build
5. **Waiting to feel "ready"** — You'll never feel 100% ready. Apply anyway

## The 80/20 Rule

80% of your learning should be from **building projects**. 20% from tutorials and courses. Most beginners do the opposite — don't be most beginners.

## What employers are actually screening for

Job descriptions are wish lists; screening criteria are much narrower. In practice a hiring loop for how to become a developer filters on four things in order: does the CV show relevant, recent, measurable work; can the candidate reason out loud through an unfamiliar problem; do they understand the fundamentals underneath the tools they list; and can they communicate a trade-off to a non-specialist. Everything else — years of experience, degree, certification count — is a tiebreaker, not a gate.

How each stage is actually judged

| Stage | What they are testing | What passes | What fails |
| --- | --- | --- | --- |
| CV screen | Relevance and evidence | Outcome bullets with numbers, keywords matched to the posting | Technology lists with no results attached |
| Recruiter call | Motivation and fit | A clear one-line story about why this role, this company | Vague answers and no questions asked back |
| Technical screen | Fundamentals under mild pressure | Thinking narrated out loud, clarifying questions first | Silent coding, then a wrong answer with no reasoning shown |
| Deep round | Depth and judgment | Concrete examples from real work, honest trade-offs | Textbook answers with no lived detail |
| Final / behavioural | Ownership and communication | Situation, action, measurable result | Blaming past teams or drifting off the question |

## Money: how to read a compensation range

A posted range is not a distribution — it is a budget. The midpoint is roughly what a well-prepared candidate at the expected level receives; the top of the band is reserved for people arriving with competing offers, unusual scope, or a scarce specialisation. That means the two levers that move your number are level and leverage, in that order. Negotiating five per cent inside a band is a smaller win than being hired one level higher, and the level is decided in the interview, not in the offer call.

- **Compare total compensation**, not base — bonus, equity, pension and benefits diverge sharply between company types.
- **Discount equity heavily** unless the company is public or you understand the strike price, vesting and liquidity terms.
- **Ask what band the role is budgeted at** rather than stating your expectation first.
- **Never negotiate from your previous salary** — anchor on the market band for the scope you are being hired for.
- **Take 48 hours** to review any written offer. It is standard and it does not put the offer at risk.

## What most people get wrong

1. Optimising for the highest advertised salary rather than the role they can sustain for three years.
2. Reading about the topic instead of producing something with it. Consumption feels like progress and rarely is.
3. Applying with an untailored CV, then concluding the market is closed.
4. Ignoring the fundamentals because the surface layer changes fast — the fundamentals are what interviews test.
5. Waiting for certainty. The information in this guide is enough to start; the rest is learned by doing.
